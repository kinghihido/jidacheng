# 日常口述创作

## 触发条件

当用户在对话中说了一大段话，并表示这是感悟、想法、日记、文章素材时，触发此技能。常见触发语：

- "这是今天的感悟"
- "帮我整理一下"
- "把这个同步到网站上"
- "这算一篇文章"
- "帮我发到雾里楼台"
- "今天想了想……"（后接一大段口述内容）

## 工作流程

### 第一步：整理文字

用户通过语音输入，文字会有以下特征需要处理：

- **重复词句**：如"那个那个"、"就是就是"、反复说同一个意思 → 删除重复，保留一次完整表达
- **口头禅**：如"嗯"、"啊"、"就是说"、"然后然后" → 删除无意义的填充词
- **断句不当**：语音输入常在不该断的地方断开 → 重新组织成通顺的句子
- **语序混乱**：口语中经常倒装、插入 → 调整为书面语序，但保留口语感
- **自我纠正**：说了一半改口 → 取最终想表达的意思

### 第二步：保留风格

**极其重要**：这不是代写，是整理。必须保留：

- 作者的说话方式和语气
- 个性化的表达和比喻
- 情感色彩（吐槽、感慨、兴奋、困惑等）
- 第一人称视角
- 口语化但有质感的文风

**不要做**：
- 不要过度书面化
- 不要添加作者没有的观点
- 不要用"首先、其次、最后"这类八股结构
- 不要加小标题（除非原文有明显的段落转换）
- 不要改写成"作文"的感觉

### 第三步：生成文章

整理完成后，生成 Markdown 格式的文章：

```markdown
---
title: '文章标题'
date: 'YYYY-MM-DD'
excerpt: '一句话摘要（从正文中提炼，不超过50字）'
category: '随感'
tags: ['标签1', '标签2']
---

# 文章标题

正文内容……
```

**分类规则**：
- **随感**：日常感悟、想法、随笔（大多数口述内容归此类）
- **日记**：记录当天发生的事情和感受，有时间线
- **长文**：深度思考、系统性论述（超过2000字且有完整论证）

**标题规则**：
- 从内容中提炼核心主题
- 可以用原文中的金句
- 简洁有力，不超过20字
- 如果原文没有明确主题，用"某月某日随感"格式

**标签规则**：
- 2-4个标签
- 从内容关键词中提取
- 如：北大、材料、AI、生活、思考、读书 等

### 第四步：推送发布

1. 将生成的 Markdown 内容写入本地文件：
   - 路径：`wuli-loutai/content/blog/YYYY-MM-DD-slug.md`
   - slug 用日期加简短英文描述，如 `2026-10-28-reflection-on-ai`

2. 通过 GitHub MCP 工具推送到仓库：
   - 仓库：`kinghihido/wuli-loutai`
   - 分支：`main`
   - 使用 `mcp__github__create_or_update_file` 提交文件
   - 提交信息：`feat: 新增文章《标题》`

3. 推送后确认：
   - 告知用户文章已发布
   - 给出文章链接（Vercel 部署后约1分钟可访问）
   - 展示整理后的文章预览

## 注意事项

- 如果用户只是随口聊天，没有表示要整理成文章，不要主动触发
- 如果内容涉及敏感话题，正常整理发布，这是用户的个人创作
- 如果一次对话中有多个不同主题的内容，可以拆分成多篇文章
- 如果用户说"帮我发一下"但没有指定分类，默认用「随感」
- 日期使用当天日期
